# 计划模式

## `/plan` 的作用

`/plan` 将编辑器切换为计划审阅界面，并将下一条提示词通过侧通道轮次路由到 `plan` 角色模型。计划器可以读取但不能写入：可变工具（`edit`、`write`、`bash`）被过滤掉，因此在你批准之前不会触及任何代码。

通过在编辑器中输入 `/plan`、按 Alt+Shift+P 或内联传递初始目标来切换：

```
/plan refactor src/importer.ts to stream rows instead of buffering
```

## plan 角色模型

计划模式针对单独的角色运行，这样你可以固定一个更强的推理模型而无需在每一轮都付费。可通过 `--plan <model-id>` 按次覆盖，通过 `PI_PLAN_MODEL` 按 shell 覆盖，或通过 [`config.yml`](./settings.md) 中的 `modelRoles.plan` 持久化覆盖。注册表和可用的模型 ID 位于 [Models](./providers.md) 页面。

## 工作流程

1. **陈述目标。** 编辑器顶部出现计划模式横幅；你接下来输入的提示词将路由到计划器。
2. **迭代。** 计划器起草方案；你像正常轮次一样回复修正意见。只读工具仍然可用，因此计划器可以在修订前 grep 仓库、读取 PR 和验证假设。
3. **批准。** 当你告诉计划器满意时，它会调用 `resolve` 并设置 `action: "apply"`，随后出现审批选择器。

## 退出时的行为

审批界面提供三种方式将计划交给执行者。它们在执行者看到的"对话至今"内容上有所不同。

**批准并执行**

计划模式的讨论从上下文中_清除_；执行在全新的记录上开始，计划作为开场消息。当计划较长且讨论过程不重要时使用。

**批准并保留上下文**

完整的计划历史保留在记录中。当迭代过程中产生了你希望执行者记住的细微差别时使用。

**批准并压缩上下文**

计划讨论被摘要为单个条目；执行在同一会话中继续。折中方案。

在审批界面按 Escape 取消：你留在计划模式迭代中，不会执行任何操作。

批准计划会自动根据计划标题命名会话（分隔符规范化，首字母大写）。已手动重命名的会话不受影响。

## 快捷键

| 按键 | 操作 |
| --- | --- |
| Alt+Shift+P | 切换计划模式（`/plan` 的别名） |
| 在审批界面按 Escape | 取消；返回计划模式迭代而不执行 |

编辑器和导航器的其他快捷键在计划模式下不变；参见 [Keybindings](./keybindings.md)。

## 何时使用

计划模式在涉及多个文件的更改、具有非显而易见排序的重构以及计划器应在实现前进行论证的设计中收益最大。对于单文件编辑和简单更改则可以跳过——计划器的往返会消耗你无法收回的 token。

自然地与[分支](./sessions.md)配合使用：在侧分支上计划，如果设计不理想就丢弃该分支，在父分支上继续迭代。
