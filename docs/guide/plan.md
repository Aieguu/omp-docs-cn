# 计划模式

## 在 omp 改动任何东西之前先规划

当难点在于决定**要改什么**时，请使用计划模式：跨文件的重构、陌生的代码库、带顺序约束的迁移，或者一个你想在实现前审阅的设计。在规划期间，omp 可以检查项目并核实假设，但它的规划轮次相对于你的工作树和系统而言是只读的。草稿作为会话工件保留；未经批准就退出不会应用它。

从目标以及会改变设计的约束开始：

```
/plan Replace the in-memory job queue with Postgres. Preserve the public API, include a rollback path, and call out every migration step.
```

你也可以直接输入不带提示词的 `/plan`，或按默认的 Alt+Shift+P 组合键，然后输入你的请求。状态行会显示 **Plan**，omp 切换到已配置的 `plan` 模型，接下来的一轮会探索和起草，而不是实现。

对于微小且已充分理解的编辑，普通模式更快。规划会多花一个模型轮次，并在执行开始之前消耗上下文。

## 从请求到审阅后的计划

1. **描述期望的结果。** 包括不可妥协的行为、相关的文件或系统，以及你将如何判断成功。
2. **让 omp 去调查。** 它读取代码和其他可用来源、核实假设，并在不改变项目的情况下构建一份 Markdown 计划。
3. **审阅草稿。** 计划就绪后，omp 会打开全屏的 **计划审阅（Plan Review）** 界面。你也可以随时用 `/plan-review` 重新打开最新的草稿。
4. **完善或批准。** 添加反馈、删除不想要的章节，或者选择实现应该如何继承这段规划对话。

一条有用的后续消息应当具体而非空泛：

```
Keep the database schema, but revise the rollout so old and new workers can run together for one deploy.
```

## 审阅与审批选项

审批选项同时控制执行与上下文。它不会改变已批准计划的内容。

| 选项 | 会发生什么 | 何时使用 |
| --- | --- | --- |
| **批准并执行** | 退出计划模式，开启一个全新的会话，并把已批准的计划交给实现模型。之前的对话记录（包括规划讨论）不会带入新的上下文。 | 计划自包含，或者你希望为实现腾出最多的上下文空间。 |
| **批准并压缩上下文** | 退出计划模式，把当前对话压缩成一份聚焦于已批准计划的摘要，然后在当前会话中实现。 | 有些探索内容要紧，但完整记录会太昂贵或太分散注意力。 |
| **批准并保留上下文** | 退出计划模式，在当前会话中实现，并完整保留规划对话。该选项会针对执行模型的上下文窗口显示大致的用量。 | 决策依赖于那些没有写进计划的细微差别。 |
| **完善计划** | 把你的审阅批注作为一轮规划轮次发回。如果你没有添加任何批注，浮层会关闭，omp 提示你输入一条后续消息。不会执行任何操作。 | 方案、顺序或范围仍需打磨。 |
| **保存并退出** | 提示输入保存位置，把计划写到那里，退出计划模式并开启一个新的空白会话，不执行该计划。相对路径从当前工作目录解析。 | 你想要一份供以后会话、审阅或交接使用的持久化计划。 |

只有在使用量已经超过执行模型上下文窗口的 95% 时，**批准并保留上下文**才不可用。请改选压缩执行或全新执行。如果会话没有可用的上下文估算值，该选项仍然可用，只是不显示用量数字。

批准后会立即开始实现。如果会话还没有名称，omp 会根据计划标题派生一个；你自己设置的名称会被保留。

### 选择实现模型

当至少有两个已配置的角色模型可用时，计划审阅会在各选项上方显示一个 **continue with**（继续使用）选择器。它默认停在 `default` 角色上。在操作区处于聚焦状态时，用 Left/Right 在批准前选择另一个角色。该选择控制的是实现，而不是产出草稿的计划器。

如果只解析出一个角色模型，选择器会被隐藏，omp 会恢复进入计划模式之前处于活动状态的模型。

## 在计划审阅中操作

底部栏始终显示当前聚焦区域中可用的控件。

| 控件 | 效果 |
| --- | --- |
| Up/Down、Enter | 选择并确认一个操作。 |
| Tab / Shift+Tab | 在目录、计划正文和操作之间移动。 |
| Page Up / Page Down、g/G | 在较长的计划中上下移动，或跳到开头/结尾。 |
| a | 批注当前聚焦的章节或可见的计划行；这些笔记会成为完善性反馈。 |
| d / Delete | 在目录侧边栏中删除选中的章节。 |
| u | 撤销最近的章节编辑或批注。 |
| c | 把当前计划复制到剪贴板。 |
| 你的外部编辑器按键 | 在 `$VISUAL` 或 `$EDITOR` 中编辑计划。 |
| Escape | 关闭审阅，既不批准也不退出计划模式。 |

目录侧边栏只在终端宽度足够且计划至少包含两个标题时出现。因此，在较窄的终端里，章节删除和章节级批注控件可能不可见；你仍然可以用普通的后续消息提示词来完善，或使用外部编辑器。

章节删除、撤销以及外部编辑器带来的改动都会在你操作时同步到会话草稿。Escape 会关闭浮层，但不会回滚这些编辑。运行 `/plan-review` 可以找回最新的计划草稿。参见[快捷键](./keybindings.md)查看或更改计划开关与外部编辑器的组合键。

## 暂停、恢复或退出

`/plan` 是一个有状态的开关：

1. 当计划模式处于活动状态时，再次运行 `/plan` 即可在不批准的情况下退出。如果存在非空草稿，omp 会请你确认。状态变为 **Plan paused**，普通工具和进入计划前的模型都会恢复，且不会执行任何操作。
2. 暂停期间，运行 `/plan <follow-up>` 会重新进入计划模式，并立即提交这条后续消息。
3. 暂停期间，再一次运行不带提示词的 `/plan`，即可彻底关闭计划模式并清除暂停状态。

在计划审阅中按 Escape 则不同：它只会关闭审阅界面。计划模式仍然活动，因此你可以继续讨论草稿，或用 `/plan-review` 重新打开它。

计划模式不能与目标模式或 Vibe 模式同时运行。进入计划模式之前，请先退出处于活动或暂停状态的冲突模式。

## 计划器模型与设置

计划模式默认启用，但不会自动启动。进入时，它会把会话临时切换到 `plan` 角色，包括该角色配置的思考级别；当你离开时会恢复之前的模型，除非你在计划审阅中选择了某个实现角色。

在 [`config.yml`](./settings.md) 中一个最小的持久化配置是：

```
plan:
  enabled: true
  defaultOnStartup: false

modelRoles:
  plan: anthropic/claude-opus-4-5:high
```

| 设置或覆盖 | 用途 | 默认值 |
| --- | --- | --- |
| `plan.enabled` | 让 `/plan` 和计划模式可用。 | `true` |
| `plan.defaultOnStartup` | 让每个全新的交互式会话以计划模式打开。已存在的/恢复的对话不会被强制进入。 | `false` |
| `modelRoles.plan` | 规划期间使用的持久化模型及可选的思考级别。 | 未设置；omp 保留当前模型 |
| `omp --plan <model-id>` | 为本次启动选择 plan 角色的模型。它**不会**进入计划模式；启动后请使用 `/plan`。 | — |
| `PI_PLAN_MODEL=<model-id>` | 为该进程选择 plan 角色的模型。`--plan` 优先。 | — |
| `cycleOrder` 与 `modelRoles` | 决定审阅时 **continue with** 选择器提供的角色模型。 | `smol`、`default`、`slow` |

如果你在计划模式活动时修改了 `plan` 角色，omp 会在下一个安全的轮次边界应用新的角色模型。

## 限制与故障排查

* **`Plan mode is disabled`** — 在活动的设置作用域中设置 `plan.enabled: true`，然后再次运行 `/plan`。
* **`Exit goal mode first` 或 `Exit vibe mode first`** — 这些模式互斥。暂停状态的计划也必须被彻底关闭后才能进入目标模式。
* **`No plan to review yet`** — 规划轮次还没有产出草稿。让 omp 先完成计划，然后使用 `/plan-review`。
* **保留上下文选项被置灰** — 对话已超过执行模型上下文窗口的 95%。请使用压缩执行或全新执行。
* **批准后压缩被取消** — omp 会保持计划已批准，但不会派发实现。请再提交一轮，从已批准的计划继续。
* **外部编辑器没有打开** — 请设置 `$VISUAL` 或 `$EDITOR`；否则请在 omp 中使用批注和后续消息提示词。
* **在 `--print` 或 JSON 输出中，启动计划模式不会激活** — `plan.defaultOnStartup` 仅限交互式，因为无头运行没有审阅界面。`--plan-yolo` 是单独的无头流程；它会自动批准，因此会有意跳过上文记载的所有人工审阅选项。
* **规划对 omp 是只读的，但对你不是** — 你自己运行的 shell 命令仍然可以更改文件或系统状态。
