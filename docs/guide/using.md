# 使用 omp

直接运行 `omp` 会打开交互式终端 UI。这是进行日常工作的常规场所：用自然语言描述一个预期结果，让 omp 检查并修改项目，审阅它的操作，然后在同一段对话中完善结果。

如果你刚完成[快速上手](./quickstart.md)，请在一个项目中启动，并发送一个有边界的请求：

```
cd my-project
omp
```

```
Find the refresh-token race, fix only the implementation and its focused tests, show me the diff, and run those tests. Do not commit.
```

按 Enter 键即可。常规工作不需要斜杠命令或特殊的提示词格式。

## 完整的任务，逐轮进行

一个可靠的交互式任务通常遵循以下循环：

1.  **说明预期结果与边界。** 指出 bug 或功能、重要的路径、任何不得改变的内容，以及应当通过的检查。
2.  **让 omp 调查。** 它会叙述进度，并把每次读取、命令或更改以卡片的形式显示在对话记录中。
3.  **在需要时介入。** 在它工作期间发送一条引导消息、回答一个问题，或拒绝一项不安全的操作。
4.  **审阅证据。** 展开工具卡片与 diff。检查被更改的路径、命令的退出状态、测试结果与最终说明。
5.  **在同一会话中完善。** 说出哪里有问题、还缺什么，例如：“保持公共签名”、“补上缺失的边界情况”，或“撤销对 `cache.ts` 的修改”。

文件更改会在 omp 工作时应用到你的工作树。除非你要求提交，否则它们不会被提交。你的编辑器、`git diff` 和对话记录仍然是最终的审阅界面。

## 读懂屏幕

具体的配色与状态栏布局取决于你的主题与设置，但交互式屏幕包含三个工作区域：

Transcript（对话记录）

你的消息、助手文本与思考、通知、提问以及工具卡片。新内容出现在底部。工具卡片会显示哪些操作处于等待、成功、失败或已取消状态；编辑卡片包括受影响的路径与 diff 摘要。

Composer（输入区）

带边框的编辑器，用于撰写下一条提示词。自动补全、附件标签、排队消息提示与临时对话框环绕在它周围。选择器或提问底部的提示行会显示适用于当前焦点面的按键。

Status line（状态栏）

默认布局显示当前模型与思考级别、工作模式、路径、Git 状态、上下文用量、成本以及会话名称。窄终端会省略或缩短部分区段。Plan、Goal、Vibe、Loop、Fast、协作及相关状态会在相关时显示于此。

状态栏不是装饰：在假设 omp 处于错误的目录、使用了错误的模型、被允许写入或上下文已用尽之前，先查看它。它的预设与区段可在 `/settings` 中更改；完整参考见[设置](./settings.md)。

## 撰写、附加并提交

| 你想… | 这样做 |
| --- | --- |
| 发送一条提示词 | 按 Enter。 |
| 插入换行 | 按 Shift+Enter、Ctrl+J 或 Alt+Enter。Windows Terminal 用户应优先使用 Alt+Enter。 |
| 提及一个项目文件 | 输入 `@`，继续输入进行模糊搜索，然后选择路径。omp 会自动把 `@path` 提及读入本轮。 |
| 补全路径 | 输入相对、父级、home 或绝对路径的一部分，使用补全列表。Tab 接受高亮的补全项。 |
| 附加图片 | 用 Ctrl+V 粘贴，或拖入、粘贴一个图片路径。输入区中的标签会确认已粘贴的附件。你也可以提及 `@path/to/image.png`；omp 会在本轮读取该文件。 |
| 附加粘贴的文本 | 正常粘贴即可。多行或较大的粘贴可以折叠成一个带编号的粘贴标签，让编辑器保持可读；删除该标签即移除该附件。 |
| 在外部编辑长草稿 | 按 Ctrl+G 打开 `$VISUAL`（未设置时回退到 `$EDITOR`），保存并关闭后文本会返回给 omp。 |
| 找回更早的提示词 | 按 Ctrl+R 搜索提示词历史。 |

你可以把文字、`@file` 提及、粘贴的文本和图片组合在一条提示词中。说明每个附件的用途；单独的路径只提供上下文，不提供意图。例如：

```
Compare @src/auth/refresh.ts with @test/auth/refresh.test.ts. The attached screenshot is the production error. Fix the race without changing the token format, then run the focused test.
```

图片输入默认会经过规范化与缩放。当当前模型无法直接接受图片时，omp 通常会请一个已配置的、具备视觉能力的模型生成描述。图片行为可在 `/settings` 中的 **Model → Vision** 与 **Appearance → Images** 下配置。

## 跟进工作并审阅卡片

工具卡片是你的提示词与最终答案之间的审计轨迹。先读标题：它标明动作、命令、路径或远程资源。然后检查它的状态与结果。

-   按 Ctrl+O 展开或折叠工具输出。可用于查看被截断的命令记录或完整的可见 diff。
-   想看纯文字视图时，按 Ctrl+Shift+O 隐藏或显示工具活动。
-   一张成功的卡片只代表该动作已完成，并不代表整个任务正确。请单独检查最后的测试或验证卡片。
-   失败或已取消的卡片仍是有用的证据。阅读错误，然后告诉 omp 是重试、换一种方法还是停止。
-   对于编辑，检查路径与新增/删除的内容。如果范围或行为有误，立即要求修正。

有关更深入的文件修改工作流与安全设置，请参见[文件操作](./files.md)。

## 回应审批与提问

如果你的审批模式或某个工具级策略要求确认，omp 会在操作前暂停并显示它想做什么。请阅读命令、目标、diff 预览与原因，而不是仅凭标题就批准。使用屏幕上显示的选择器按键，在提供的允许或拒绝选项中选择。Escape 会取消该提示；关闭提示不代表已获批准。

当 omp 需要征求你的输入时，它可能会显示提问对话框：

-   使用 Up/Down 移动，按 Enter 选择单个答案。
-   对于多选问题，按 Space 切换选项，然后按 Enter 继续。
-   使用 **Other** 行输入自定义答案。当对话框提供解释性说明时，可在该行上按 `n`。
-   若有多个问题，用 Tab、Shift+Tab 或 Left/Right 切换标签页；在最后一个标签页上审阅并提交。
-   按 Escape 取消而不是猜测。之后你可以在输入区说明缺失的约束。

默认的 **Yolo** 审批模式允许常规的读取、写入与执行操作，因此你可能看不到审批提示。当你希望在写入和命令执行前得到确认时，请在 `/settings` 的 **Interaction → Approvals** 下选择 **Always ask**，或使用 `omp --approval-mode always-ask` 启动。

## 引导、排队、停止与继续

你可以在 omp 工作期间继续输入。提交键决定该消息是影响当前轮次，还是等待下一轮。

| 操作 | 默认按键 | 使用时机… |
| --- | --- | --- |
| 引导当前轮次 | Enter | 当前的做法需要纠正，例如：“不要更改 schema”、“使用现有的 helper”或“调查后停止”。 |
| 排队一条后续消息 | Ctrl+Q 或 Ctrl+Enter | 当前任务应先完成，例如：“在那之后，解释一下迁移风险。” |
| 把已排队的输入取回输入区 | Alt+Up 或 Shift+Up | 你排错了文字，或想编辑待处理的消息。 |
| 中断当前操作 | Escape | 某个轮次、本地 shell/Python 转义、重试或其他进行中的操作应当停止。 |
| 继续先前的意图 | 发送 `.` 或 `c` | 你在恰当的节点中断，希望 omp 直接继续而不必重新陈述任务。 |
| 重试上次失败的助手轮次 | Alt+R | Provider 或轮次失败，应当再次尝试同一个请求。 |

引导消息是给**当下**的；后续消息是给**agent 让出之后**的。待处理消息条会显示已排队的内容。`steeringMode`、`followUpMode` 与 `interruptMode` 设置控制排队消息是一起排空还是一条条地排空，以及引导是立即中断还是等待。

Escape 对焦点敏感。如果自动补全或选择器处于打开状态，第一次按键会关闭该表面。在主输入区中它会中断正在进行的工作。它不会退出 omp。在 Loop 模式下它会停止当前迭代，同时让 Loop 保持启用；再次运行 `/loop` 可禁用 Loop。确切的行为见[运行模式](./modes.md)。

## 选择模型与思考级别

在任务给你理由之前，请使用默认值。当前选择始终显示在状态栏中。

| 控件 | 结果 |
| --- | --- |
| `/model` 或 Alt+M | 打开模型中心，检查或修改持久化的模型-角色分配。 |
| `/switch` 或 Alt+P | 为当前会话选择一个临时模型，而不更改已保存的角色分配。 |
| Ctrl+P / Ctrl+Shift+P | 在配置的角色-模型顺序中向前或向后循环。 |
| Shift+Tab | 循环切换活动模型支持的思考力度，包括配置了 Auto 时。 |
| Ctrl+T | 在对话记录中显示或隐藏思考块。这只会改变可见性，不会改变推理力度。 |

更高的思考级别可以改善困难推理，但通常会提高延迟和 token 用量。不支持可配置思考的模型会这样告知，而不会做出更改。当选择 Auto 时，一旦轮次被分类，状态栏就会显示解析出的力度。

持久化分配、快速循环顺序与会话级覆盖，参见[模型角色](./roles.md)。

交互式工作模式改变的是轮次的行为，而不是你与 omp 对话的方式。状态栏会告知你何时有模式处于激活状态：

-   **Plan** 会先探索并提出方案，在获得你批准之前不修改工作树。参见[Plan 模式](./plan.md)。
-   **Goal**、**Vibe**、**预走查(Prewalk)**、**Loop**、**Fast** 及相关控件是专门的流程。请从普通的交互式轮次开始，并在[运行模式](./modes.md)中有意地选择它们。
-   如果 omp 意外地拒绝编辑，或在某一轮结束后仍继续运行，请先检查模式区段。用相应的斜杠命令退出或禁用该模式，而不要用重复的提示词与其对抗。

## 自行运行本地命令

带前导转义符的命令会直接从输入区运行，而不需要让模型选择或调用任何东西：

```
! git status
!! git diff --stat
$ print(2 + 2)
$$ import os; print(os.getcwd())
```

| 前缀 | 行为 |
| --- | --- |
| `! command` | 在你的用户 shell 中运行该命令，在 TUI 中流式显示结果，并将其纳入对话上下文。 |
| `!! command` | 运行并显示命令，但把它的输出排除在模型上下文之外。 |
| `$ code` | 在会话的共享 Python 内核中运行 Python，并把结果纳入上下文。`$` 之后必须有空格，因此像 `$HOME` 这样的文字仍是文字。 |
| `$$ code` | 运行 Python 并显示结果，而不把输出加入模型上下文。 |

按 Escape 可取消正在运行的 shell 或 Python 转义。一条成功的 `! cd path` 还会移动 omp 的交互式工作目录。这些命令以你的本地用户权限运行，可以立即更改文件；`!!` 和 `$$` 只是把输出排除在模型上下文之外，并非安全沙箱。

## 在会话之间移动而不丢失工作

你无需退出即可改变对话状态：

| 命令 | 用途 |
| --- | --- |
| `/tree` | 移动到当前会话中更早的消息或另一条分支。当一轮走偏时使用它。 |
| `/branch` | 从同一会话文件中更早的消息开启一条替代线程。 |
| `/fork` | 在尝试另一条独立路线之前，把这段对话克隆到一个新的会话文件中。 |
| `/resume` | 打开该项目的会话选择器。 |
| `/new` | 启动一个全新会话，同时把当前会话保留在磁盘上。 |
| `/session info` | 显示当前会话 id、路径、谱系与统计信息。 |
| `/compact` | 当上下文计量偏高时，对较早的活动上下文进行汇总，同时保留可导航的历史。 |

会话树与会话选择器会显示各自的导航提示。Escape 会先清除活动的搜索，然后关闭选择器。完整的分支、恢复、导出与交接行为见[会话](./sessions.md)。

## 退出与恢复

使用 `/exit`、`/quit`、`/q` 或 Ctrl+D 有序退出。Ctrl+D 会保存一条非空的、尚未发送的输入区草稿；恢复该会话时会把它还原一次。Ctrl+C 清空输入区，半秒内再按一次则退出，所以当你的意思是“离开并保留草稿”时，应优先使用 Ctrl+D。

从同一项目目录重新启动最近的会话：

```
omp -c
```

使用 `omp -r` 可打开项目会话选择器。这也是 SSH 或终端断开后的恢复途径：持久化的对话记录会被回放；如果仍有一个正在写入的进行中尾部，也会一并回放。

### 常见的卡住状态

| 你看到的情况 | 恢复办法 |
| --- | --- |
| 按键在移动列表而不是编辑提示词 | 选择器、自动补全菜单或提问获得了焦点。阅读其底部提示，或按 Escape 将其关闭。 |
| 排队的消息有误 | 按 Alt+Up 或 Shift+Up，编辑恢复出的文本并再次提交。 |
| agent 正在走错误的路线 | 用 Enter 发送一条具体的引导消息。如果继续会有害，按 Escape，审阅已经修改的内容，然后给出纠正。 |
| 你意外地停掉了一个进行良好的轮次 | 发送 `.` 或 `c` 以继续先前的意图。 |
| 响应失败 | 阅读错误卡片，然后按 Alt+R 重试，或用 `/model` 更换模型。 |
| 工具输出或 diff 看起来不完整 | 按 Ctrl+O 将其展开。 |
| 调整大小或重新连接后终端显示错乱 | 按 Alt+L 重置并重绘显示。 |
| omp 只检查但不编辑 | 检查 Plan 模式以及屏幕上显示的审批提示或策略。审慎地批准该操作、退出 Plan，或调整 **Interaction → Approvals**。 |
| 上下文用量接近上限 | 先完成当前的思路，然后运行 `/compact`。参见[记忆与压缩](./memory.md)。 |
| 终端断开或 omp 已退出 | 回到项目目录并运行 `omp -c`；如果它不是最近的项目会话，则使用 `omp -r`。 |
| 你记不住某个快捷键 | 运行 `/hotkeys`，然后参见[快捷键](./keybindings.md)了解所有动作与重映射语法。 |
