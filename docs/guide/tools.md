# 工具索引

## 直接提出你想要的结果

通常你不需要自己挑选或调用工具，直接用日常语言告诉 omp 你想要什么即可：

```
Find where checkout retries are configured, change the default to three, and verify the behavior.
```

omp 会挑选合适的搜索、编辑和执行能力。只有当你想限定处理方式时才点名某个能力，例如“只检查、不要运行它”“这个页面需要登录，请用浏览器打开”或“不要使用 shell”。

在会话中使用 `/tools` 可以查看当前模型与项目实际可用的能力。这是权威的实时视图：设置、已安装的程序、模型支持、任务深度、自定义工具以及已连接的 MCP 服务器都可能改变它。

## 控制可用的能力

*   打开 `/settings`，使用**工具 → 可用工具**进行持久的开/关切换。相关的控制项还分布在**文件**、**Shell**、**记忆**和**任务**下。参见[设置](./settings.md)。
*   用 `omp --tools read,glob,grep` 启动受限会话，或用 `omp --no-tools` 启动不含任何内置工具的会话。命令行层面的限制只作用于该会话。
*   可以给会话使用 `omp --approval-mode always-ask`、`write` 或 `yolo`。持久的等价配置是 `tools.approvalMode`，以及按能力区分的 `tools.approval.<name>` 策略（`allow`、`prompt` 或 `deny`）。参见[工具审批](../reference/approvals.md)。
*   `tools.xdev` 默认开启。它把使用较少和动态发现的能力放进按需目录，而不是预先加载每一条描述。关闭它只会改变呈现方式，不会改变允许执行的内容。

下面的审批类别描述的是潜在影响：

*   **读取**检查状态，不会有意去改变它。
*   **写入**可以更改文件或持久的用户数据。
*   **执行**可以运行代码、控制进程、使用网络账户或操作某个应用程序。
*   **混合**取决于具体操作。例如，读取 GitHub 属于读取，而 checkout 或 push 属于执行。

内置审批模式目前默认是 `yolo`，它会自动放行上面三个类别。如果你希望在写入和执行操作前得到确认，就选择 `always-ask`；也可以通过按能力的策略彻底拒绝某项能力。项目、插件、自定义工具或 MCP 服务器依然是必须由你信任的代码；审批提示并不是沙箱。

| 能力（选择名） | 你可以要求什么 | 可用性与前置条件 | 类别 | 配置 / 了解更多 |

| 跟踪阶段（`todo`） | 维护一个可见的多步骤清单，并把工作标记为受阻、进行中或已完成。 | 在 `todo.enabled` 下默认开启；目标模式/子代理模式可能改用各自的完成界面。 | 读取 | [子代理与 Agent Hub](./subagents.md) |

## 记忆与改进

记忆默认关闭。在期待 `/tools` 中出现这些能力之前，请先在 `/settings` → **记忆**下选择一个后端。

| 能力（选择名） | 你可以要求什么 | 可用性与前置条件 | 类别 | 配置 / 了解更多 |
| --- | --- | --- | --- | --- |
| 回忆持久知识（`recall`） | 检索相关的事实或过往的经验教训。 | 与 `hindsight` 或 `mnemopi` 后端一起可用。 | 读取 | [记忆](./memory.md) |
| 留存持久知识（`retain`） | 为将来的会话保存某个事实、决策或经验教训。 | 与 `hindsight` 或 `mnemopi` 后端一起可用。 | 读取（遵循记忆服务自身的策略） | [记忆](./memory.md) |
| 跨记忆反思（`reflect`） | 综合或关联已存储的知识。 | 与 `hindsight` 或 `mnemopi` 后端一起可用。 | 读取 | [记忆](./memory.md) |
| 维护 Mnemopi 记忆（`memory_edit`） | 检查、更新、合并或删除本地 Mnemopi 存储中的记录。 | 仅与 `mnemopi` 后端一起可用。 | 读取（遵循记忆子系统自身的策略） | [记忆](./memory.md) |
| 捕获可复用的经验教训（`learn`） | 保存经验教训，并在合适时把它转化为受管理的技能。 | 默认关闭；需要 `autolearn.enabled` 以及 `local`、`hindsight` 或 `mnemopi` 记忆后端。 | 混合：仅存入记忆可视为读取；写入文件或技能为写入 | [记忆](./memory.md) |
| 维护受管理的技能（`manage_skill`） | 创建、改进、检查或停用自动学习的技能。 | 随 `autolearn.enabled` 默认关闭；通常只在顶级会话中暴露。 | 写入 | [技能](./skills.md) |

## 面向成果的内置工作流

这些是面向用户的入口，而非通用工具，但它们可能代替你使用上面的若干能力。

| 工作流 | 起始操作 | 作用 | 了解更多 |
| --- | --- | --- | --- |
| 代码审查 | 运行 `/review`，然后选择基准分支、未提交的更改、某个提交、某个 PR 或自定义说明。 | 将 diff 分发给多个审查 agent，并返回按优先级排序的发现。 | [代码审查](./review.md) |
| 创建提交 | 运行 `omp commit`；只想预览时加上 `--dry-run`。 | 分析更改，提出 conventional commit 分组与 changelog 更新建议，然后提交；推送为可选项。 | [创建提交](./commit.md) |
| 目标模式 | 需要引导式访谈时运行 `/guided-goal`；当目标已经明确时运行 `/goal`。 | 跨轮次持续朝一个持久且有预算的目标推进。其模式专属辅助能力仅在目标模式需要时才出现。 | [目标模式](./goal.md) |
| 计划模式 | 在要求执行有风险或模糊不清的实现前，先运行 `/plan`。 | 将规划阶段限制为只读探索，并在执行前呈现一份计划供你审阅。 | [计划模式](./plan.md) |
| Vibe 模式 | 运行 `/vibe [prompt]`，启动直接的、持久化的快速/优质工作会话。 | 把主会话变成一个指挥者，负责启动、引导、验证并停止持久的工作会话。 | [Vibe 模式](./vibe.md) |
| 自动研究 | 向干净的 Git 工作树添加 `autoresearch.sh` 基准测试工具，然后运行 `/autoresearch [goal]`。 | 在专用的 `autoresearch/*` 分支上反复运行由基准支撑的实验。某些重置/丢弃控件具有破坏性；请先查看仪表盘与基线。 | [运行模式](./modes.md) |

目标模式、子代理或某些模型家族使用的内部完成与推理辅助能力，刻意不作为用户可选的能力，也不会作为可配置项显示。

## 添加能力

实时的 `/tools` 列表可以包含比上面内置项更多的内容：

| 来源 | 如何变得可用 | 信任与配置 |
| --- | --- | --- |
| 自定义工具 | 会话启动时，omp 会发现在用户层或项目层编写的 JavaScript/TypeScript 工具。 | 它们以你的用户身份运行。加载前请审查项目代码；参见[自定义工具](./custom-tools.md)。 |
| MCP 服务器 | 已连接的服务器会发布它们自己的工具与资源；默认允许发现项目中的 `.mcp.json`/`mcp.json`。 | 服务器可能访问外部账户或执行本地代码。通过 [MCP](./mcp.md) 配置并完成其身份认证。 |
| 扩展与插件 | 受信任的扩展可以注册工具；插件可以把工具与命令、agent、规则或服务器配置打包在一起。 | 启用前请检查其源代码与声明的内容；参见[编写扩展](./extension-authoring.md)与[插件](./plugins.md)。 |
| 宿主应用程序 | SDK、RPC 与 ACP 宿主可以为各自的会话提供能力。 | 可用性与审批都由该宿主控制；参见 [SDK](./sdk.md)、[RPC](./rpc.md) 与 [ACP](./acp.md)。 |

## 报告能力问题

自动工具 QA（`xd://report_issue`）随 `dev.autoqa` 默认开启。当 omp 检测到与该能力文档约定相矛盾的行为时，它可以记录一份报告；第一条报告会询问你是否同意分享它。使用 `omp grievances` 检查已记录的报告，并在 `/settings` 中更改**工具 → 开发者 → Auto QA** 以关闭报告功能。这条支持路径不会给 omp 提供另一种修改你项目的方式。

如果你期望的能力缺失，先检查 `/tools`，再核对上文中该能力的启用设置与前置条件。更改已发现的工具、扩展、插件或 MCP 配置后，请重启会话，以便重建实时目录。
