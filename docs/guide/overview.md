# 项目概览

## 从一个真实任务开始

omp 是一个以终端为先的编码 agent，专为那些远不止“粘贴一段代码片段”的工作而生。在项目内运行它，描述你想要的结果，它就能调查代码库、编辑文件、运行命令并解释结果——你无需在编辑器、shell 与聊天窗口之间来回搬运上下文。

如果你是第一次来，请从[快速上手](./quickstart.md)开始，它涵盖了安装与 Provider 认证。然后打开一个项目，启动交互式会话：

```
cd path/to/your-project
omp
```

用自然语言给它一个具体的任务：

```
Find why the user-session test hangs, fix the root cause, run the smallest relevant test, and explain what changed.
```

omp 会流式输出响应，并把文件操作、命令等其余工作以紧凑的卡片形式展示。按 Ctrl+O 可以展开卡片，查看它的完整输出或 diff。你可以继续追问、纠正方向，也可以按 Escape 停止当前轮次。

一个好的首个任务应当目标明确，并且有办法验证它。如果你只想要一个解释，就说“只调查，不要修改”。对于大型或有风险的工作，请从[计划模式](./plan.md)开始，这样你就可以在实现之前先审阅方案。

## 为什么使用 omp

软件工作很少止步于生成代码。一个有用的改动，可能需要找到正确的文件、理解现有的约定、安全地重命名符号、运行一个针对性的测试、检查正在运行的进程，或者查看一个 pull request。omp 把这条工作循环保持在同一个会话中，并且直接使用你机器上已有的代码仓库和开发环境。

它非常适合这样的开发者：

- 更愿意在终端里指挥并审阅工作；
- 在已有的、讲究上下文与验证的代码仓库中工作；
- 想自行选择模型 Provider，而不是被绑定在某一家上；
- 今天需要一个快速的调查，明天需要一个可恢复的多步骤改动；或者
- 希望一套工作流能从单个 agent 扩展到规划、并行工作和共享会话。

omp 可以在你的环境中修改文件并运行命令，所以请像审阅队友的改动一样审阅它的工作；对于敏感项目，请使用[审批控制](../reference/approvals.md)。提示词和相关上下文会发送给你选定的模型 Provider；各种集成也可能会联系它们各自对应的服务。

## 作为用户，你会注意到什么

**从请求到验证的一条闭环**

要一个结果，而不是把代码复制进浏览器。当任务需要时，omp 可以组合使用仓库搜索、编辑、命令、[语言感知的代码智能](./code-intelligence.md)、[实时调试](./debugging.md)、[浏览器操作](./web.md)与 [GitHub 上下文](./github.md)。它的工作过程在会话中始终可见。

**模型由你选择**

接入 API key、OAuth、订阅、网关或本地 Provider，然后为日常任务、快速任务、更深入的推理以及规划选择模型。先从 [Provider](./providers.md) 开始；想调优路由或行为时，再使用[设置](./settings.md)。

**可以放下、也可以回来继续的工作**

会话默认保存在本地。你可以恢复之前的工作；想在保留历史的情况下尝试不同方向时，可以开一个分支；当别人需要这些上下文时，可以把会话分享出去。相关的用户控制请参见[会话](./sessions.md)。

**动手实现之前先规划**

运行 `/plan` 开启一次独立的规划轮次，完善方案后再决定何时执行。它很适合迁移、架构调整以及那些对操作顺序有要求的工作。参见[计划模式](./plan.md)。

**任务真正能拆分时并行工作**

让 omp 把任务中相互独立的部分委派给子代理，例如一次审计多个软件包。你可以在它们工作期间观察进度并加以引导。参见[子代理](./subagents.md)。

**一套可以不断扩展的工作流**

项目规则与[技能](./skills.md)教会 omp 你们团队的工作方式；当内置能力不够用时，扩展与 [MCP 服务器](./mcp.md)还可以加入公共集成。

## 一条实用的学习路径

1.  **先让一个提示词跑通：**[快速上手](./quickstart.md) 涵盖安装、认证、终端设置和你的第一个会话。
2.  **学会交互控制：**[使用 omp](./using.md) 讲解界面、编辑器、消息队列与 one-shot 模式。
3.  **把有用的成果留下来：**[会话](./sessions.md) 涵盖恢复、分支、分叉、导出与分享。
4.  **按你的目标选择下一篇指南：**

| 你想…… | 请前往…… |
| --- | --- |
| 高效地控制一个正在进行的会话 | [Slash 命令](./slash-commands.md)与[快捷键](./keybindings.md) |
| 接入或更换模型 | [Provider](./providers.md)与[设置](./settings.md) |
| 在动代码之前设计一个较大的改动 | [计划模式](./plan.md) |
| 调查符号、诊断或正在运行的进程 | [代码智能](./code-intelligence.md)与[调试](./debugging.md) |
| 拆分相互独立的工作，或分享实时会话 | [子代理](./subagents.md)与 [Collab](./collab.md) |
| 从脚本或其它程序中使用 omp | [CLI 参考](../reference/cli.md)、[RPC 模式](./rpc.md)或 [SDK](./sdk.md) |
| 添加团队指令或集成 | [技能](./skills.md)、[MCP](./mcp.md)与[编写扩展](./extension-authoring.md) |

不确定该走哪条路？先完成[快速上手](./quickstart.md)，在你熟悉的一个代码仓库里跑一个小任务，然后再继续[使用 omp](./using.md)。
