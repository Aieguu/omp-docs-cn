# 上下文文件

## 四个文件

将其中一个文件放在项目旁（或放在 `~/.omp/agent/` 下以获得全局作用域），omp 会在下一次提示时自动发现。无需重新加载，无需配置项——发现机制完全基于文件系统。

| 文件 | 作用 | Agent 何时可见 |
| --- | --- | --- |
| `AGENTS.md` | 项目笔记——约定、注意事项、代码位置。 | 在会话开始时注入系统提示。 |
| `SYSTEM.md` | 完全替换内置系统提示。仅在你清楚移除了什么时使用。 | 在会话开始时替换系统提示。 |
| `APPEND_SYSTEM.md` | 追加在内置系统提示之后。 | 在会话开始时拼接到系统提示末尾。 |
| `RULES.md` | 粘性规则，在每轮对话中重新注入，使其在长时间对话中持续生效。 | 每轮都重新附加，而非仅在开始时。 |

## 存放位置

项目文件从当前工作目录向上遍历，深度为 20，因此任何祖先检出根目录都可以放置。全局文件位于 `~/.omp/agent/` 下，适用于所有会话。

```
<repo>/AGENTS.md            # 项目笔记（也会从子目录中遍历发现）
<repo>/.omp/SYSTEM.md       # 项目级：替换系统提示
<repo>/.omp/APPEND_SYSTEM.md
<repo>/.omp/RULES.md

~/.omp/agent/AGENTS.md      # 全局笔记
~/.omp/agent/SYSTEM.md      # 全局级：替换系统提示
~/.omp/agent/APPEND_SYSTEM.md
~/.omp/agent/RULES.md
```

相邻的其他框架文件也会被发现：Codex `AGENTS.md`、Claude `CLAUDE.md`、Cursor rules、`.clinerules`、Copilot instructions、opencode 上下文文件。每个已加载的条目都会在 [`/extensions`](./slash-commands.md) 中显示其来源路径。

## 解析顺序

当同类型文件存在多个时，omp 按以下顺序拼接，从最通用到最具体：

1. 全局——`~/.omp/agent/<FILE>`
2. 项目祖先——从 `cwd` 向上遍历找到的最近的 `<FILE>`
3. 项目根——仓库根目录的 `.omp/<FILE>`

对于 `SYSTEM.md`，最后一个生效：项目级的 `.omp/SYSTEM.md` 会替换全局文件，而非拼接。对于 `AGENTS.md`、`APPEND_SYSTEM.md` 和 `RULES.md`，所有匹配的文件会通过分隔符连接，因此全局的前言加上各项目的笔记会同时生效。

## AGENTS.md 实践

将 `AGENTS.md` 视为 Agent 的 README。约定、构建命令、那个看似无害但实际承载关键功能的文件、默认的目录布局。Agent 在会话开始时读取一次，所以保持精简——冗长的文件每轮都会消耗上下文。

```
# Project notes for the agent

## Conventions
- Bun, not Node. Use `bun test`, not `npm test`.
- React Router v6 with file-based routes under `src/routes/`.
- No utility classes inside <Prose>; use plain HTML tags.

## Where things live
- `src/components/docs/` &mdash; PageHeader, Prose, nav.ts
- `src/routes/docs/` &mdash; one file per page

## Don&rsquo;t touch
- `bun.lock` &mdash; regenerated by `bun install`.
- `public/clips/` &mdash; binary assets, do not rewrite.
```

## RULES.md 与粘性行为

`RULES.md` 是你需要确保某个指令持续执行时使用的文件。omp 会在每轮对话中将其内容附加到用户当前消息附近，使其保持在模型的近期窗口内，即使经过多轮对话也是如此。将其用于硬性约束（"永远不要提交密钥"、"在输出前始终运行 `just test`"），而非一般性笔记——那些应放在 `AGENTS.md` 中。

## 替换系统提示

`SYSTEM.md` 会整体替换内置系统提示。你会失去 omp 精心调优的指令，包括工具使用指南。除非你明确需要不同的 Agent 人格，否则优先使用 `APPEND_SYSTEM.md`。

```
# ~/.omp/agent/APPEND_SYSTEM.md

You are pairing with a security-focused engineer. When reviewing diffs,
call out: missing input validation, unsafe deserialization, secrets in
logs, and authn/authz changes that broaden access.
```

## 禁用发现

| 标志 | 效果 |
| --- | --- |
| `--no-context-files` | 跳过本次运行的 `AGENTS.md`、`SYSTEM.md` 和 `APPEND_SYSTEM.md` 发现。 |
| `--no-rules` | 跳过本次运行的 `RULES.md` 发现和注入。 |
| `--system-prompt <text\|@file>` | 从 CLI 覆盖系统提示——优先级高于 `SYSTEM.md`。 |

运行 `omp -p '/extensions'` 可确认实际加载了哪些文件。完整标志详情请参见 [CLI 参考](./settings.md)，其他自定义入口请参见 [Skills](./skills.md)、[Prompt 模板](./prompt-templates.md) 和 [Hooks](./hooks.md)。
