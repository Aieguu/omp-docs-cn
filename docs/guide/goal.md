# 目标模式

目标模式将单个目标转化为自主驱动的会话。使用 `/goal <objective>` 设置一次目标后，每轮结束后 omp 都会注入一个隐藏的继续引导，重新提交相同的目标。当模型调用 `goal` 工具并设置 `op: "complete"` 且证明每个交付物时、当 token 预算用完时、或者当你暂停或取消时，循环停止。

当下一步很明确但总工作量不确定时——长迁移、扇出清理、"持续运行直到测试套件通过"——它是合适的工具。一次性起草使用 [`/plan`](./plan.md)；盲目地重新提交相同提示词 N 次使用 `/loop`。

## 启动目标

目标模式受 `goal.enabled` 设置控制。在 `~/.omp/agent/config.yml` 中启用一次，然后：

```
/goal port the importer to streaming and update the call sites
```

omp 将目标固定到会话中，将 `goal` 工具注入活动工具集，并将目标作为你的第一轮提交。你传递的文本成为模型在每次继续时看到的字面 `<objective>` 块，因此请像写简报一样撰写：交付物、成功标准、任何排除捷径的条件。

省略参数时，`/goal` 会打开多行编辑器来编写目标。

## 子命令

所有操作针对当前会话的目标。不带子命令的 `/goal` 针对活动或暂停的目标打开交互菜单。

| 命令 | 效果 |
| --- | --- |
| `/goal set <objective>` | 设置目标。如果目标已处于活动或暂停状态则拒绝；请先取消或恢复。 |
| `/goal show` | 打印目标、状态、已用 token / 预算 / 剩余以及经过时间。 |
| `/goal pause` | 停止继续引导。使用量统计冻结；目标记录保留在会话中。 |
| `/goal resume` | 重新启用继续并调度下一次引导。 |
| `/goal drop` | 确认后删除目标记录。累计使用量保留在会话日志中。 |
| `/goal budget <N\|off>` | 替换 token 预算。`N` 是总 token 的正整数；`off` 清除上限。 |

当目标已处于活动状态时，`/goal` 打开管理菜单（`Show details`、`Adjust budget…`、`Pause`、`Drop`）；对于暂停的目标，菜单首先提供 `Resume`。

## 预算约束循环

没有预算时，目标模式会一直运行到模型自行决定完成。对于无人值守的会话，这通常不是你想要的。使用 `/goal budget 200000` 设置上限；模型也可以在通过 `goal` 工具创建目标时通过传递 `token_budget` 设置自己的上限。

预算统计在目标处于活动状态的每一轮中，输入、输出和缓存读写 token 的消耗。当使用量超过上限时，状态变为 `budget-limited`，下一次继续引导被替换为收尾提示：模型被告知不要开始新的实质性工作，要总结进度，并列出剩余工作和阻碍。预算耗尽明确**不是**完成——模型被指示保持目标活动状态而不是调用 `complete` 来逃避上限。

使用 `/goal budget <N>` 提高预算，循环即恢复。设置 `off` 完全移除上限。

## 检查和取消

`/goal show` 是读取路径。它打印实时目标、目标状态（`active`、`paused`、`budget-limited`、`complete`、`dropped`）、预算已用 token、剩余 token 和经过的秒数。

要停止循环：

- `Esc` 取消当前轮次但保持目标模式开启；下一次继续引导照常触发。
- `/goal pause` 暂停继续而不丢失目标或其使用历史。
- `/goal drop` 在确认后完全结束目标。

目标在会话压缩和 `/branch` / `/fork` 后仍然存在。使用 `/move` 切换工作目录时，目标附属于会话而非目录。

## 与普通提示的区别

在普通会话中，omp 在每轮后停止并等待你。在目标模式下，当目标处于 `active` 状态时，有三件事发生变化：

- 系统提示词前会添加一个 `<goal_context>` 块，包含目标和实时预算数字。
- 每轮不调用 `goal({op:"complete"})` 的结束后，会排队一个隐藏的 `user` 引导（从可见记录中抑制）。
- `goal` 工具被强制注入活动工具集。模型使用 `goal({op:"get"})` 读取自身预算，使用 `goal({op:"complete"})` 在验证每个交付物符合当前仓库状态后结束循环。

完成提示是有意严格的：模型被要求将目标重述为具体交付物，将每个交付物映射到文件或命令证据，并在声称完成前重新读取实际当前状态。狭隘的检查不能证明宽泛的声明。

## 使用场景对照

- **`/goal`** —— 当目标跨越多轮且模型应自行决定何时完成时。验证完成情况。支持预算。
- **`/loop`** —— 当你有一个提示词需要固定次数重新提交或在指定时间窗口内运行时。无目标，无完成语义。适用于"运行我的测试套件五次并报告不稳定测试"。
- **`/plan`** —— 当你希望在任何编辑发生前，先对计划角色模型进行一次只读起草时。一轮，然后结构化交接给执行者。

可以组合使用：先用 `/plan` 规划工作范围，接受计划，然后对生成的简报使用 `/goal` 来完成执行的长尾工作。
