# Prewalk

## 用强模型规划，用快模型实现

Prewalk 是普通 omp 会话内的一次性模型交接。从你最信任的模型开始，让它理解一个陌生的代码仓库、识别风险并组织工作。一旦该模型建立了 todo 列表并开始修改项目，omp 就会把当前会话切换到一个更快或更便宜的目标模型来继续实现。

一个实用的首次运行是：

```
omp --model @slow --prewalk-into @smol
```

然后像往常一样描述完整的结果。对话、仓库上下文、todo 和改动都留在同一个会话中；prewalk 更换的是继续完成剩余工作的模型，而不是任务本身。

这可以降低那些“规划困难但执行例行”的改动的成本和延迟。这是一种权衡，不是免费的质量提升：目标模型仍然要理解规划者的 todo、在实现暴露出错误假设时进行调整、测试结果并完成清理。当工作需要反复的设计决策、微妙的调试或高风险编辑时，请全程使用一个有能力的模型。

## 启用并选择目标

Prewalk 默认禁用。用 `--prewalk` 为一个新会话布防：

```
omp --prewalk
```

这会使用分配给 `smol` 角色的模型。为了让这个选择可预期，请在 `/model` 的 **Roles** 中分配该角色，或在 `~/.omp/agent/config.yml` 中配置：

```
modelRoles:
  smol: anthropic/claude-haiku-4-5
```

要为一次启动选择不同的目标，给 `--prewalk-into` 传入一个角色别名或模型选择器。这个 flag 也会布防 prewalk，因此不需要再搭配 `--prewalk`。

```
omp --prewalk-into @smol
omp --prewalk-into openai/gpt-5-mini
```

需要一个稳定且精确的选择时，使用完整的 `provider/model-id`。已配置的角色还可以携带思考级别，模型选择器也可以包含一个，例如 `provider/model-id:medium`。omp 使用与其他模型控制相同的角色和模型匹配规则来解析目标。

要持久化开启，设置：

```
omp config set prewalk.enabled true
```

等价的 YAML 是：

```
prewalk:
  enabled: true
```

启用该设置后，每个新会话都会自动布防并以 `@smol` 为目标。用 `--prewalk-into <model-or-role>` 为某次启动覆盖目标，或用 `--no-prewalk` 让特定会话保持在它的起始模型上：

```
omp --no-prewalk
```

`--no-prewalk` 不能与 `--prewalk` 或 `--prewalk-into` 组合。持久化设置不会自动布防一个被恢复的对话；如果你想在继续会话时交接，请显式传入 `--prewalk`。

## 识别交接

布防后的 prewalk 让起始模型先调查并确立实现计划。当 todo 可用时，第一次完成的文件编辑就会启动交接。这次编辑本身由起始模型完成；目标模型接收同一个会话并从那里继续。

你会看到让生命周期一目了然的通知：

-   **Armed（已布防）**——指明解析出的目标，并说明 omp 正在等待 todo 列表和第一次编辑或写入。
-   **Switched（已切换）**——指明目标，并报告切换发生在第一次编辑或写入之后。
-   **Nothing to switch（无可切换）**——目标模型和思考级别已经与活动会话一致，因此 omp 解除布防而不是执行一次空操作。

如果模型仍在阅读、搜索或讨论方案，交接会等待。如果 todo 可用但尚未改动任何项目文件，它会保持布防。在 todo 不可用的配置中，第一次完成的文件编辑可以直接交接。

Prewalk 是一次性的。切换之后它不再布防，后续的编辑不会引发更多模型更换。目标模型成为本次活动会话余下时间的当前模型，但切换不会改写你保存的模型角色设置。模型指示器和切换通知会显示当前激活的模型。

## 在活动会话中布防

运行 `/prewalk` 可以在不重启、不修改 `prewalk.enabled` 的情况下布防交接：

```
/prewalk
```

该命令解析 `@smol`，检查其可用性，并在成功布防时显示目标。它不接受目标参数；如果需要其他目标，请在启动 omp 时使用 `--prewalk-into`。

如果 prewalk 已经布防，`/prewalk` 会保留现有目标而不是替换它。交接发生后，你可以用常规模型控制选择另一个当前模型，然后再次运行 `/prewalk` 来创建另一次一次性交接。

## 选择把模型质量花在哪里

一个好的 prewalk 目标应当已完成认证、快速、便宜，并且在该任务所需的语言和工具上可靠。把预期节省与修复薄弱实现的成本进行比较：

| 工作形态 | 建议选择 |
| --- | --- |
| 先宽泛调查，再重复更新大量调用点 | 强力起始模型，快速目标 |
| 清晰的计划，随后是例行测试或机械编辑 | 强力起始模型，便宜目标 |
| 安全敏感的迁移，或带有隐藏不变量的行为 | 全程保留有能力的模型 |
| 每个结果都会改变下一个假设的调试 | 通常跳过 prewalk |
| 小而显而易见的编辑 | 直接从便宜的模型开始；prewalk 增益很小 |

更强的规划者应当留下具体、有序的 todo，并从一个有代表性的编辑开始。如果目标模型经常需要重新发现约束条件，就换一个更有能力的目标，或者干脆不要交接。

## Prewalk 与子代理

本页描述的是主会话交接。task 子代理是独立的委派运行，拥有自己的上下文和模型选择；布防主会话并不意味着每个子代理都会 prewalk。只有在你使用委派代理、并希望在这些运行内部采用相同的“先规划后切换”模式时，才需要单独配置子代理 prewalk。参见[子代理](./subagents.md)。

## 故障排除

-   **启动时没有出现布防通知**——除非 `prewalk.enabled` 为 `true`，或启动包含 `--prewalk` 或 `--prewalk-into`，否则 prewalk 是关闭的。被恢复的会话不会从设置继承自动布防；请显式传 flag。
-   **`Warning: prewalk disabled — model … not found`**——目标角色或选择器未能解析。在 `/model` 中检查生效的 `smol` 分配，或使用 `omp models find <name>` 返回的完整选择器。
-   **`Warning: prewalk disabled — no API key for …`**——认证目标 Provider，或选择其 Provider 已配置的模型。omp 会在未布防 prewalk 的情况下继续启动。
-   **`/prewalk` 报告模型或 API key 错误**——`/prewalk` 总是使用 `@smol`。修复该角色或其 Provider 凭据；要使用其他目标，请用 `--prewalk-into` 重启。
-   **已布防但尚未切换**——让起始模型完成调查、建立 todo 并开始第一处项目编辑。只读工作和讨论不会消耗交接。
-   **第一次编辑发生了，但没有跟随切换**——检查编辑是否失败、目标是否已经与当前模型和思考级别一致，或可见通知是否说明目标解析期间 prewalk 被禁用。
-   **`/prewalk` 提示已为另一个模型布防**——现有的一次性目标被保留。让它完成交接，或以期望的 `--prewalk-into` 目标启动新会话。
-   **切换后质量下降**——选择更强的目标，分配更合适的思考力度，或者对那些设计贯穿实现全程的任务使用 `--no-prewalk`。
