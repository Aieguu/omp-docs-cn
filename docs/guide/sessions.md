# 会话

## 工作会自动保存

像平常一样启动 omp 并开始工作：

```
cd ~/work/api
omp
```

并没有 Save 命令。omp 会把已完成的对话消息和工具活动记录到与该工作目录关联的会话中。退出后可以这样回来继续：

```
cd ~/work/api
omp -c
```

`-c` 会在当前目录继续该终端的最近一次会话。如果该终端的面包屑记录不可用，omp 会使用该目录中最近修改过的会话；如果不存在，则开启一个新会话。

保存按条目完成进行。仍在流式传输的文本要等响应完成后才会提交，因此一次硬崩溃可能丢失末尾的部分响应，但会保留它之前已完成的工作。安全继续的方法见 [崩溃恢复](#崩溃恢复)。

如果你完全不想要本地会话记录，可用 `omp --no-session` 启动。该次运行无法作为已保存的会话被恢复、删除或分叉。显式的导出或分享仍会创建或上传一份独立的副本。

## 开始、继续或选择会话

根据你掌握的情况选择对应的操作：

| 你想要的 | 操作 |
| --- | --- |
| 开始不相关的工作 | `omp`，或在 omp 内使用 `/new` |
| 在当前目录继续该终端最近的工作 | `omp -c` |
| 从已保存的工作中选择 | `omp -r`，或在 omp 内使用 `/resume` |
| 恢复一个已知的会话 | `omp -r <id-or-path>`，或 `/resume <id>` |
| 启动时总是继续最近的会话 | 在 `/settings` 中启用 **Auto Resume**，或运行 `omp config set autoResume true` |

`/new` 会开启一个新的已保存会话，并让当前会话保留在选择器中。它与 `/clear` 不同：`/clear` 只重置模型当前的对话上下文，同时保持同一个会话不变。

### 使用会话选择器

在启动前运行 `omp -r`，或在 omp 打开时输入 `/resume`。选择器会先显示当前文件夹的会话。

*   输入文字可按标题、会话 ID、项目路径或对话文本搜索。搜索还能找到长会话深处的提示词。
*   按 ↑/↓ 和 Enter 选择。
*   按 Tab 可在**当前文件夹**与**所有项目**之间切换。所有项目视图会显示每个会话的工作目录。
*   已置顶的会话排在最前。**interrupted**、**aborted** 或 **error** 等状态文字有助于识别未完成的运行。
*   按 Delete，或在搜索框为空时按 Backspace，可在确认后删除高亮显示的会话。

当你从另一个已存在的项目恢复会话时，omp 会切换到该会话记录的工作目录。如果记录中的目录已不存在，交互式启动会提议将会话移动到你的当前目录。

使用 `/session info` 查看当前会话的 ID 和文件路径。对于 `-r`、`/resume`、`/pin` 和 `--fork`，一个简短且唯一的 ID 前缀通常就足够了。

## 让已保存的工作易于查找

### 命名与置顶

与其依赖第一条消息的预览，不如给重要的工作一个稳定的标题：

```
/rename Streaming importer investigation
/pin
```

`/pin` 会在恢复列表顶部切换当前会话的置顶状态。`/pin <session-id>` 可切换另一个已保存会话的置顶状态，而无需打开它。如果你将会话移动到另一个项目目录，置顶状态会随会话保留。

### 将会话移动到另一个项目

如果这段对话现在应归属于另一个 checkout 或 worktree，请移动它，而不是依赖所有项目选择器：

```
/move ../api-v2
```

目标必须是一个目录。omp 会移动已保存的会话及其工件，更新其工作目录，并使其可从目标项目的恢复列表中发现。

### 删除

根据接下来希望发生什么来选择命令：

| 操作 | 结果 |
| --- | --- |
| 在恢复选择器中删除 | 删除高亮显示的会话及其工件 |
| `/session delete` | 删除当前会话并返回选择器 |
| `/drop` | 删除当前会话并立即开启一个新会话 |
| `/new` | 保留当前会话并开启一个新会话 |

删除是不可逆的。如果之后可能还需要它，请先导出或复制 `/session info` 显示的 JSONL 文件。

## 分支还是分叉？

两者都会保留你已有的对话，但对替代路线的组织方式不同。

|  | 分支 | 分叉 |
| --- | --- | --- |
| 命令 | `/branch` | `/fork` |
| 保存为 | 同一会话中的另一条路径 | 具有新 ID 的全新已保存会话 |
| 你选择 | 一条更早的用户消息，用于修改并重新发送 | 当前状态；无消息选择器 |
| 适用场景 | 探索同属于一条规范历史的备选方案 | 有风险、可丢弃或需单独分享的工作线 |
| 返回原会话 | 会话内的 `/tree` | `/resume` 并选择父会话 |

`/branch` 会打开用户消息选择器。选择新方向应开始的那条提示词；omp 会回退到它之前的位置，并把该提示词放回编辑器供你修改。被放弃的后续内容仍保留在同一会话中，可用 `/tree` 再次查看。

`/fork` 会把当前已保存的会话及其工件复制到一个新会话中，然后在新副本中继续。父会话保持不变，并单独出现在恢复选择器中。若要从更早的时间点分叉，请先导航或分支到该时间点，再运行 `/fork`。

在 shell 中，可把某个已知的已保存会话直接分叉到当前项目：

```
omp --fork <session-id>
omp --fork ./received-session.jsonl
```

使用 `/tree` 可在同一会话内保存的多条路径之间切换。[会话树](./session-tree.md) 介绍了导航、标签、活动路径，以及分支和分叉究竟保留了哪些内容。

## 导出、分享与导入

### 导出本地审阅副本

`/export` 会写出一个自包含的 HTML 视图并在浏览器中打开它：

```
/export
/export ./review/importer-session.html
```

无需打开交互式会话即可导出已有的 JSONL 文件：

```
omp --export ./session.jsonl ./session.html
```

HTML 用于阅读，而非用于恢复。它可能包含对话文本、工具输出、路径和模型上下文，因此请将其视为敏感内容。

### 分享加密链接

在会话中运行 `/share`，或在 shell 中分享一个已保存的会话：

```
omp share <session-id-or-path>
```

默认流程会在你的客户端中加密会话快照并上传加密后的数据块。解密密钥位于 URL 片段中，不会发送到存储服务器。对已配置的敏感信息，默认启用涂抹处理（secret redaction），但它不能替代你发送前的检查：任何拿到完整链接的人都能读取该快照。较大的分享内容可能被裁剪以符合服务限制；此外，配置的自定义分享处理程序可能使用不同的目的地和隐私模型。

当另一个人需要一份关于当前状态和后续步骤的简明说明时，请在分享前使用 `/handoff [focus]`。

### 在可编辑副本中继续

分享链接或 HTML 导出无法重新导入到活动会话中。若要交接可编辑的内容，请发送 `/session info` 报告的 JSONL 路径；接收者应将其分叉到自己的当前项目中：

```
cd ~/work/api
omp --fork ./received-session.jsonl
```

这会创建一个新的本地会话，并让收到的文件保持不变。而 `omp -r ./received-session.jsonl` 会直接打开那个确切的文件，并在其记录的工作目录仍存在时采用该目录。

omp 还可以把本地的 Claude Code 或 Codex 历史记录导入到全新的 omp 会话中：

```
omp --from-claude
omp --from-codex
```

每条命令都会打开一个特定来源的选择器。在已有的 omp 会话中，`/resume @claude` 和 `/resume @codex` 会打开同样的导入选项。

对于需要公共 JSONL 结构而非产品工作流的工具，请参阅 [会话格式](../reference/session-format.md)。

## Profile、位置与隐私

会话在两个层面内划分：

1.   **Profile。** `omp --profile work` 使用相互隔离的设置、身份认证、缓存和会话。恢复选择器只会看到当前活动的 Profile。
2.   **工作目录。** 在某个 Profile 内部，omp 按项目对会话进行分组。选择器从当前文件夹组开始；按 Tab 可显示该 Profile 的其他项目。

默认 Profile 的常规位置是 `~/.omp/agent/sessions/`。命名 Profile 通常使用 `~/.omp/profiles/<name>/agent/sessions/`。XDG 配置和目录覆盖项可以更改这些路径，因此 `/session info` 才是活动会话的权威位置来源。

当某次启动必须在特定目录中保存和查找会话时，使用 `--session-dir <path>`。从该自定义位置恢复时，请复用同一个标志。当你希望在不同客户端、身份或工作上下文之间实现持久隔离时，优先使用 Profile；当只有某一段对话属于另一个项目时，优先使用 `/move`。

已保存的 JSONL 文件和工件位于本地，但它们可能包含提示词、源代码片段、工具结果、文件路径以及命令打印出的敏感信息。请像对待源代码和凭据一样保护会话目录。`--no-session` 会阻止生成会话记录，但不会撤销工具对文件的更改，也不会撤销你显式导出或分享的副本。

## 崩溃恢复

在终端断连、进程崩溃或强制重启之后：

1.   回到同一项目并运行 `omp -c`。
2.   如果那不是正确的对话，请运行 `omp -r`，输入一个有辨识度的短语，并检查标记为 **interrupted** 的会话。
3.   在发送另一条提示词之前，阅读最后几条已完成的消息以及任何待处理工具警告。
4.   在要求 omp 重复某条命令之前，先核实外部副作用。记录可能表明某个工具结果从未被记录下来，即使该命令在 omp 之外改变了某些东西。

omp 会保留崩溃前已完成的条目，并忽略不完整的末尾记录。它不会臆造被中断的工具调用缺失的结果，也不会臆造流式响应中未保存的尾部。

## 故障排查

### 选择器提示没有会话

*   按 Tab；你可能只查看了当前文件夹。
*   检查你是否像之前一样使用了同一个 `--profile` 启动。
*   如果会话使用了 `--session-dir`，请再次传入该目录。
*   在离开会话前使用 `/session info`，记下它的确切路径。

### `-c` 打开了错误的工作

`-c` 优先选择与当前终端关联的最近会话，然后才是该目录中最新的会话。请使用 `omp -r` 明确选择，或对经常返回的会话使用 `/rename` 和 `/pin`。

### 找不到已知的 ID

打开 `omp -r`，按 Tab，然后在所有项目视图中搜索。如果多个会话开头相似，请使用更长的 ID 前缀。Profile 与自定义会话目录是相互独立的搜索范围；请切换到原来的 Profile，或传入原来的 `--session-dir`。

### 分叉或删除不可用

分叉需要持久化，因此请在不带 `--no-session` 的情况下重新启动。删除需要一个实际存在的已保存文件；一个全新的空会话可能还没有任何可删除的内容。在移动、删除或分叉之前，请等待流式响应结束，或先中止它。

### 项目目录被重命名或移除

在交互式终端中按 ID 恢复。对于记录目录已不存在的会话，omp 会提议将其重新挂载到当前目录。对于已存在但不同的项目，请正常恢复它，并在你有意重新归属时使用 `/move <path>`。

命令行标志见 [CLI 参考](../reference/cli.md)，所有交互式命令见 [斜杠命令](./slash-commands.md)。
